## 本機啟動

已安裝依賴，可直接雙擊本資料夾的 **`啟動遊戲.cmd`**，保留開啟的終端機視窗即可遊玩。按 Ctrl+C 可停止伺服器。

也可以在 PowerShell 執行：

```powershell
cd 'C:\Users\acer\我的雲端硬碟\2026Codex\外勤養成V1\clinic-visit-challenge'
npm run dev -- --port 5173 --open
```

瀏覽器開啟 <http://127.0.0.1:5173/>。若連接埠已使用，Vite 會顯示另一個可用網址，請以終端機輸出為準。

環境：Node.js 22.12+、24 或26以上的支援版本。重新安裝時執行 `npm ci`。本次使用 Node.js 26.2.0；安裝時遇到本機憑證鏈問題，已使用 `$env:NODE_USE_SYSTEM_CA='1'` 載入 Windows 系統信任憑證，沒有停用 TLS 驗證。

伺服器預設只綁定 127.0.0.1。手機尺寸已在瀏覽器模擬驗證；若要用實體手機連線，可在可信任的區域網路執行 `npm run dev -- --host 0.0.0.0`，再以電腦區網 IP 開啟。這會讓同網路裝置存取開發伺服器，請於測試完畢後關閉。

## 七關操作方式

1. 首頁按「開始遊戲」，選擇目前已開放的關卡，再選該關限定的一項產品或主題。
2. 按「開始第N關」，以方向鍵／WASD或手機方向按鈕行走，也可點選目標地點自動前往。
3. 外勤走到教官、藥師或醫師的定位點後會自動開啟對話；關閉後可按E／Enter或交流按鈕再聊。在人物旁讀完三段氣泡後，接受本項10題考驗；也可返回探索。
4. 選擇A～D並確認送出，答案鎖定後顯示正確答案。10題全對100分才算本項合格；90分仍不合格，可回顧錯題並重試。
5. 合格後選「繼續挑戰本關其他產品／主題」，累積至少5項不同產品／主題合格，才可選「下一關」進入其題庫選擇；依序解鎖至第七關。已通過關卡可重玩，重新整理後從本機紀錄恢復。
6. 正式來源連線失敗或此關無可用題庫時，可重試或匯入符合分類的CSV。七關不以示範題或其他分類替代。

首頁可查看遊戲說明、略過進場動畫，右上角切換音效。音效預設關閉，採 Web Audio API 合成。V5在本機儲存音效偏好及任務完成標記；只記錄合格題數，不儲存逐題作答明細或個人身分。瀏覽器的「減少動態效果」設定會自動套用。

3D畫布聚焦後，方向鍵／WASD控制人物，`E`／`Enter`互動；`Alt`＋方向鍵旋轉鏡頭，`+`／`-`縮放、`Home`重設。放開按鍵、離開畫布焦點或切換視窗會停止行走。捲動頁面可從場景外側操作。不支援WebGL2或顯示內容遺失時，自動切換原有簡易場景，可繼續拜訪與答題；簡易場景沿用點擊移動。首頁與簡易備援保留原創SVG，正常交流使用3D人物旁氣泡。

## 題庫資料格式

產品與題目和介面分開管理。`products.json` 的 `id` 必須對應 `questions.json` 的 `productId`。

```json
{
  "id": "demo-1",
  "productId": "demo",
  "prompt": "題目內容",
  "options": ["選項A", "選項B", "選項C", "選項D"],
  "correctIndex": 0,
  "explanation": "原始解析",
  "explanationReviewed": true
}
```

`correctIndex` 為0～3。只有 `explanationReviewed: true` 且有解析文字時才顯示解析。新增真實藥品內容前，請使用已核准仿單、原題庫或公司審核教材，不以示範題代替產品知識。

### 相容原「營一大挑戰」CSV

2026-10-24 已唯讀檢查現有 `互動式問答/quiz-web/src/services/quizDataService.ts`，確認原題庫使用 `產品、藥理分類、類型、分數、題目、選項A、選項B、選項C、選項D、正確答案`。新遊戲讀取產品、題目、四選項與答案；原題庫的「分數」不會影響本遊戲現行固定每題10分的規則。

| 用途 | 英文欄名 | 已支援的中文欄名 |
| --- | --- | --- |
| 產品 | product | 產品、產品名稱、商品名稱 |
| 題目 | question | 題目、問題 |
| 四選項 | optionA～optionD | 選項A～選項D、選項 A～選項 D、A～D |
| 答案 | answer | 正確答案、答案 |
| 成分（選填） | ingredient | 成分 |
| 圖片（選填） | image | 產品圖片 |
| 解析（選填） | explanation | 解析、答案解析 |
| 解析審核（選填） | explanationReviewed | 解析已審核 |

答案接受 A～D、1～4 或與唯一選項完全一致的文字。CSV採UTF-8，可含BOM，支援引號內逗號及換行。解析審核欄只有 `true、1、yes、是、已審核` 才視為有審核標記。

同一產品、同一題幹會去重。缺題幹、缺選項、選項重複或答案無效的列會略過，並顯示匯入警示。少於五道有效題目的產品會停用「開始拜訪」。匯入資料由 React 當純文字呈現，不執行HTML。

### 正式題庫接入方式

遊戲啟動時已自動讀取 `src/config/quiz.ts` 的正式公開CSV，無須另外填網址或設定檔。每次重新整理或按「重新讀取正式題庫」會重新讀取來源；產品頁顯示載入狀態、產品數及有效題數。連線失敗會保留本次已載入資料（第一次開啟時保留本地示範資料），可按「重試連線」。不保存正式題庫的離線快取。

產品選擇頁也保留「接入產品 CSV 題庫」，可直接選擇本機CSV，或貼上可匿名存取的其他公開CSV網址。可先匯入 `public/sample-quiz.csv` 測試。手動匯入會替換本次題庫並保留示範產品；重新整理後會重新載入正式CSV。手動匯入優先於尚未完成的正式讀取，不會被遲到回應覆蓋。

僅在需要改接其他公開CSV時，複製 `.env.example` 成 `.env.local` 並覆寫預設網址：

```dotenv
VITE_QUIZ_CSV_URL=https://docs.google.com/spreadsheets/d/e/你的公開發布ID/pub?output=csv
```

重新啟動 Vite；正式建置時修改設定則需重新 `npm run build`。讀取不攜帶登入憑證，網址需允許跨來源讀取。原題庫目前沒有解析欄位時，遊戲只顯示正確答案，不自行補寫解析。

正式CSV已自動啟用，已使用真實網路資料完成桌機、手機的產品選擇及五題100分通關驗收，題幹、四選項及答案逐一對照該次Google回應。產品名稱沿用「產品」欄，分類優先沿用「顯示分類」，其次為「藥理分類」；未提供成分、照片、解析時，不自行補寫。原Google Sheets、分享權限、排行榜與原專案程式均未修改。需登入的來源請保留本地檔案匯入；任何 `VITE_` 環境變數都會進入前端，切勿放入私人憑證。

## 素材替換

3D診所與人物以本專案程式建立，沒有下載外部3D模型；首頁、對話、虛構示範產品與徽章保留自製SVG。實際產品照片使用已核對的本機既有照片複本。Three.js及OrbitControls採MIT授權，圖示由 `lucide-react` 提供（ISC授權），見套件LICENSE與`THIRD_PARTY_NOTICES.txt`。

- 換產品圖：修改 `products.json` 的 `image`，或填CSV的 `image / 產品圖片`。建議使用透明背景圖片，置於 `public/assets/products/`。
- 換3D場景、人物：修改`src/three/buildClinic.ts`與`person.ts`；鏡頭、拾取、渲染位於`createClinicRenderer.ts`。首頁、對話及簡易場景的SVG仍由`src/data/assets.ts`管理。
- 診間人物位於背景與前景桌子之間，`consultation-desk.svg` 負責遮住人物下半身，使醫師呈現坐在桌後的狀態。
- 外勤沿預設路徑移動；3D人物以手臂、髖部及膝部關節形成步態。簡易場景保留V2的SVG／CSS動畫。
- 重建示範素材：執行 `python scripts/generate_assets.py`，會覆寫同名示範SVG。更換正式素材前請先備份，避免日後重建覆蓋。
- 圖片載入失敗會顯示替代畫面，答題流程仍可操作。診間前景圖若缺少則隱藏該覆蓋層。
- 遊戲介面與SVG中文字體優先使用「微軟正黑體」。其他系統若未安裝該字型，會依瀏覽器可用字型替代。

### 本機實際產品照片

已從本工作區 `../產品照片/` 優先取用22張照片，再從本機既有 seminar 與教育訓練資料夾補入3張，合計23項產品、25張實拍照片。正式題庫其餘57項（含教材主題）維持待補。對照以原題庫完整產品名為準，不刪除劑量或劑型做模糊配對。

照片與題庫是獨立資料層：`src/data/productPhotos.json` 管理產品名稱、照片路徑與包裝標示，`csvLoader.ts` 在讀取產品資料時套用本機對照；不修改原CSV。先採已核對本機照片，未對應時採CSV圖片欄，再沒有則顯示待補。選品頁顯示同產品的各規格圖與標示；診所任務、醫師對話沿用第一張照片並顯示該張包裝規格。

Pitastatin兩個來源檔名的2mg／4mg與包裝相反，本專案複本已依包裝實際標示命名與顯示，來源檔未改名或修改。照片規格只描述該張包裝，不會改寫題庫產品名稱、答案或用法用量。

完整來源、規格核對、未使用素材與待補名單見 [產品照片對照與待補清單](docs/產品照片對照與待補清單.md)，SHA-256紀錄見 `output/product-photo-audit.json`。

新增照片時，先核對實際包裝，再修改 `scripts/product-photo-sources.json` 的明確對照，執行：

```powershell
npm run photos:sync
npm test
npm run build
```

同步腳本只建立檔案複本並產生對照與清單，不改動來源圖片。若目標已有不同內容的同名檔案會停止，避免覆蓋。照片保留原始位元內容，不裁切、不重壓縮；只在畫面以contain縮放呈現。更新後重新整理遊戲即可載入新對照。
